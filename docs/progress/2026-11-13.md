## 实测与证据

环境为 Windows 上的 WSL 2 / Ubuntu-24.04，使用临时网络命名空间内的回环接口。默认 WSL 网络仍出现代理/网络模式警告，本次未更改 VPN 或系统网络设置；未验证 Mac 和实际服务器。

- 严格编译：`cc -std=c11 -Wall -Wextra -Wpedantic -Werror -O2 src/sender.c -o build/rudp-send` 通过。
- 正式入口：`make clean`、`make check` 通过，原始输出见 [验证日志](2026-11-13-validation.txt)。发送端共 7 个测试方法，各含多个场景。
- 0 B、1 B、1024 B、1025 B、1 MiB、10 MiB 文件与模拟对端接收数据的 SHA-256 一致。
- 首次请求/确认丢失时重传；重传保留原始报文和会话 ID。
- 9 类无效报文不能推进状态；错误源端点的正确格式报文不能完成握手。
- 对端静默、持续无关包、零窗口、远端 ERROR、最终确认全部丢失均明确失败，测试条件下在 2 秒内退出。
- 无效参数、缺失文件、目录、FIFO、超过上限的稀疏文件均拒绝，不等待对端。

复现（已安装依赖的 Linux）：

```sh
make
sudo unshare --net sh -c 'ip link set lo up && make check'
```

`make check` 可以在正常网络的 Mac/Linux 直接运行；上面隔离方法只适用于具备相应权限的 Linux。
