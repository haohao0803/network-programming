## 功能验收

1. 文件覆盖 0 B、1 B、1 KiB、1 MiB、10 MiB，成功收发后 SHA-256 一致。
2. DATA、ACK、START、FIN 及其确认丢失时能重试或在限定时间内明确失败。
3. 乱序和重复不会重复写文件，重传包不会被当作新传输。
4. 非法长度、错误版本、未知类型和错误传输 ID 不改变当前会话。
5. 接收缓存有界，零窗口时具备有界探测与恢复办法。
6. 对端退出、磁盘失败和目标已存在时行为明确。
7. 完整接收并成功保存后才报告接收成功，部分文件处理规则写入运行说明。
8. Mac 与 Ubuntu 都能构建和完成正常通信，跨机器联调记录环境、地址与结果。

## 实验安排

先比较停止等待版与完整滑动窗口版，四个场景各重复三次，共 24 次，固定测试文件并记录哈希。

| 场景 | 初始建议参数 | 主要观察 |
| --- | --- | --- |
| 正常 | 无额外故障 | 正确性、耗时、有效吞吐量 |
| 高延迟 | 双向各增加 50 ms，记录实测 RTT | 窗口和超时行为 |
| 随机丢包 | 两方向各配置 1% 丢包，保存种子 | 重传、完成率、耗时 |
| 乱序与重复 | 每方向 delay 20 ms、reorder 10%、duplicate 1%，验证实际生效 | 去重、重组、缓存 |

预跑后固定参数与拓扑。netem 乱序依赖延迟队列，场景配置及实际生效验证一并保存。场景结束后恢复实验环境。

另设隔离的限速链路与竞争流量实验，观察拥塞控制。基础实验完成后加入 TCP 参照，保持文件、链路和统计口径一致。

每次记录运行 ID、Git 提交号、系统/内核、模式、文件大小/哈希、网络参数/种子、重复次数、成功或失败、耗时、有效吞吐量及重传次数。失败计入完成率，超时与成功耗时分别报告。有效吞吐量按成功交付的原始文件字节计算。

保留参数日志，RTT/RTO/cwnd 曲线可追溯到原始数据。Mac/Linux 正常通信与 Linux 受控实验分别记录环境。
