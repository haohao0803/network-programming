# 可靠 UDP 协议草案

用于 2026-11-11 的接口讨论，以下规则待全组确认。当前 udp-probe 为独立环境检查示例。

## 线格式

第一版为单发送端向单接收端传一个文件，采用 IPv4 UDP。多字节整数用网络字节序，逐字段编码和解码。

| 字段 | 字节 | 含义 |
| --- | --- | --- |
| magic | 4 | ASCII RUDP |
| version | 1 | 版本 1 |
| type | 1 | START=1、START_ACK=2、DATA=3、ACK=4、FIN=5、FIN_ACK=6、ERROR=7 |
| reserved | 2 | 第一版发送为 0，接收校验为 0 |
| transfer_id | 4 | 配合源 IP/端口识别会话 |
| sequence | 4 | DATA 分片序号或 ACK 累计确认位置 |
| payload_length | 2 | 有效载荷长度 |
| receive_window | 2 | 从累计确认位置起允许接收的窗口跨度，单位为分片 |

固定头长 20 字节，DATA 载荷最多 1024 字节。校验实际长度、版本、类型、ID、字段范围。START 载荷包含分片数 uint32 和文件大小 uint64，均与分片规则一致。第一版限制文件大小和分片数，单次传输序号不回绕。

输出路径由接收端本地 CLI 指定。分片长度必须与文件大小、序号匹配。

## ACK 与窗口

DATA 从 0 编号，ACK.sequence 是下一个未连续收到的序号。接收端缓存窗口内的乱序分片，ACK 通告从累计确认位置起可接收的窗口跨度，保持缓存有界。

初版建议累计 ACK 加超时回退重传。超时从最早未确认分片恢复，接收端去重。若改用选择确认，需同时修改两端编码、窗口规则和测试。

发送窗口受配置上限、cwnd 和接收窗口共同约束，单位为分片。检查重复 ACK、延迟 ACK 和超过已发送范围的 ACK。零窗口需要有界探测和恢复规则，START_ACK 通告初始接收窗口。

## 计时与拥塞接口

使用单调时钟。LPCAQ 计算 RTT、RTO、cwnd 和 ssthresh，haohao0803 提供新确认、超时等事件。

- 初始 RTO 建议 1 秒，固定上下限。
- 仅使用新确认且未重传报文的 RTT 样本，避免重传歧义。
- 超时退避，连续失败达到预算后明确退出。
- 定义慢启动、拥塞避免、超时收缩，明确重复 ACK 是否触发快速重传。
- 全组确认时固定公式、初值、单位、上限和 C 接口，补充可手算例子。

模块提供初始化、读取 RTO/窗口、新 ACK 和超时接口。发送循环负责网络与重传，参数模块负责计算。日志记录时间戳、事件、RTT、RTO、cwnd、ssthresh、接收窗口。

## 会话与结束

START/START_ACK 可重试，相同源端点与 transfer_id 的重复 START 返回已有会话状态，避免重新截断文件。

先写临时文件，收齐预期长度且保存成功后进入完成确认。SHA-256 由实验工具核对，线上最终校验是否加入由全组确认。

FIN/FIN_ACK 可重试，接收端保留有界完成状态并对重复 FIN 再次确认。保留时间与发送重试预算共同确定。最终确认全部丢失时，发送端报告未获得完成确认。

磁盘失败、目标已存在与部分文件处理规则在 CLI 设计时固定。空文件由握手直接进入结束阶段。未知源、错误 ID 和非法字段保持会话状态一致。
